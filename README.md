# 00929 Buffett Investment Monitor

針對 **00929 復華台灣科技優息 ETF** 全部成分股的巴菲特式 3M 選股
（Management / Moat / Margin of Safety）與財報即時追蹤系統。

每次執行會：抓取最新成分股名單 → 逐檔載入財報 → 計算指標 → 交叉驗證估值 →
偵測紅旗 → 產生 100 分 Buffett Score → 與上次結果比對 → 輸出 Dashboard 與報表。

---

## 本 repo 有真實分析結果

`reports/` 與 `docs/index.html` 是**每日排程實際跑出來的**，不是範例。
最近一次執行涵蓋 50 檔成分股、全部可排名，資料來自公開資訊觀測站彙總報表
與證交所／櫃買中心 OpenAPI，皆為官方來源。

> **開發環境的限制**：本專案的建置環境封鎖了所有台股來源
> （`openapi.twse.com.tw`、`mopsov.twse.com.tw`、`www.fhtrust.com.tw`、
> `api.finmindtrade.com` 一律 403），因此所有真實資料都是透過
> GitHub Actions 取得的。在你自己的機器上執行不會有這層限制。

想先看版面與計算邏輯而不連網，執行 `make demo`（合成資料，報表會顯著標示）。

## 資料來源（規格第十九節：官方優先）

| 用途 | 來源 | 說明 |
|---|---|---|
| 成分股名單 | 復華投信官方持股 API → 人工名單 | 依序嘗試，**全部失敗即中止** |
| 5–10 年歷史財報 | **公開資訊觀測站彙總報表** | 官方，免金鑰 |
| 最新一期財報 | 證交所／櫃買中心 OpenAPI | 官方權威值，覆蓋同期數字 |
| 股價、本益比、殖利率 | 證交所 `BWIBBU_ALL`、`STOCK_DAY_ALL` | 官方每日 |
| 資本支出、股利、月營收、PE 序列 | FinMind v4 | 需免費 token，**只補空缺** |

三層優先序的意思是「**同一欄位**誰說了算」，不是誰整筆覆蓋誰：
合併一律逐欄位進行，來源沒給的欄位保留既有值。整筆替換會讓官方端點
沒有的欄位（例如研發費用）平白消失——資料不會出錯，只會憑空變少。

**為什麼成分股不是向證交所拿**：ETF 持股明細由**發行投信**公告，不是交易所。
已比對證交所 OpenAPI 全部 143 個端點，`成分`／`PCF`／`申購買回`／`holding`／
`composition` 皆 0 筆命中。00929 的持股由復華投信公告。

復華官網頁面是 JS 渲染，但其前端呼叫的是一個純 JSON 端點
（`/api/assets?fundID=ETF21&qDate=…`），系統直接打該端點，
**不需要瀏覽器自動化**——少一個沉重相依，且網站改版時 API 通常比 DOM 選擇器穩定。
回應含 `etf002` 欄位，系統會驗證它確實是 `00929`，
內部基金代號若變動會直接報錯而不是默默分析錯的基金。
`qDate` 為必填且非交易日回空，因此會自動往前回溯最多 10 天找最近的交易日。

`scripts/probe_constituent_sources.py` 與 `probe-sources.yml` 是找出這個端點的
診斷工具，保留下來供日後 API 變動時重新探測（手動觸發、唯讀、不寫任何檔案）。

**多年度歷史怎麼拿**：證交所 OpenAPI 的每個端點都**只回傳最新一期**，
不接受日期參數，因此歷史另尋來源。公開資訊觀測站的**彙總報表**
一次請求就涵蓋該期別全市場（約 1060 家公司、1.5 MB）：

| 代碼 | 報表 |
|---|---|
| `t163sb04` | 綜合損益表 |
| `t163sb05` | 資產負債表 |
| `t163sb20` | 現金流量表 |

查詢方式為 `POST /mops/web/ajax_t163sb04`，參數 `TYPEK`（`sii` 上市／`otc` 上櫃）、
`year`（民國年）、`season`（`01`–`04`，`04` 即年度數）。

> **注意網域**：新版 `mops.twse.com.tw` 是 SPA，舊路徑只回 65 bytes 的轉址殘骸；
> 彙總報表仍由**舊網域 `mopsov.twse.com.tw`** 供應。查詢參數是從新版前端的
> chunk（`/mops/assets/t163sb04.js`）反推出來的，該檔內含完整的查詢欄位定義。

之所以走彙總報表而非逐檔查詢，是請求量的問題：逐檔是
50 檔 × 約 40 期 × 3 張表 ≈ **6000 次請求**，必定被擋；
彙總報表把十年壓到 **96 次**，而且抓一次就涵蓋全市場，
換股後新成分股的歷史已經在快取內。

年度數抓十年、季度數只抓最近兩年——長期指標本來就是年度的，
近幾季則供 QoQ／YoY 與財報事件追蹤使用。已定案的期別（會計年度結束滿 15 個月）
永久快取不再重抓；季報會在年度查核完成時被追溯調整，所以這個門檻刻意保守。

**彙總報表給不了什麼**：現金流量表只有三大活動淨額，**沒有資本支出明細**，
因此 FCF 與盈再率無法由此推得，會標示「資料不足」。
不會拿投資活動淨額冒充資本支出——那會把金融資產買賣算進去。
這些細項（連同股利、月營收、歷史本益比）由 FinMind 補：
免費 token 於 <https://finmindtrade.com> 註冊取得，設為環境變數 `FINMIND_TOKEN`，
**未設定不會中斷執行**，只是相關指標標示資料不足，而不是用近似值假裝算得出來。

> 00929 追蹤的是「特選臺灣**上市上櫃**科技優息指數」，成分股含上櫃公司，
> 所以同時接了櫃買中心的端點。

## 設定 FINMIND_TOKEN（SOP）

沒有 token 系統照常執行，只是 **FCF、盈再率、殖利率、歷史本益比分位、產業別**
會標示「資料不足」，而且**安全邊際整項算不出來**——估值需要至少 2 種方法交叉驗證，
沒有 token 時只有 PEG 可用，所以「最便宜 Top 10」是空的、不會有任何 BUY 判斷。

設好之後可評分分母會從 **85 分回到 100 分**。

### 一、取得 token

1. 到 <https://finmindtrade.com> 註冊免費帳號
2. 登入後於帳戶頁面複製 API token

### 二、設定到 GitHub（每日排程用）

1. 進入 repo 的 **Settings → Secrets and variables → Actions**
2. 按 **New repository secret**
3. Name 填 `FINMIND_TOKEN`（**大小寫必須完全一致**，拼錯不會報錯，只會靜默地繼續當作沒設定）
4. Secret 貼上 token → **Add secret**

工作流程已經有 `FINMIND_TOKEN: ${{ secrets.FINMIND_TOKEN }}`，設好即生效，不必改任何檔案。

### 三、本機執行（選用）

```bash
export FINMIND_TOKEN=你的token
make update
```

**不要**把 token 寫進 `config/sources.yaml` 或任何會進版控的檔案——
程式只從環境變數讀（`sources.yaml` 裡的 `token_env` 只是變數**名稱**）。

### 四、確認真的生效

手動觸發一次 `daily-update` 後，檢查 `reports/README.md`：

| 檢查點 | 沒生效 | 生效 |
| --- | --- | --- |
| 「資料來源」段落 | 沒有 FinMind | 出現 `FinMind:...` 條目 |
| 「資料缺口」段落 | 每檔都寫「未設定 FINMIND_TOKEN 環境變數」 | 該則訊息消失 |
| 逐檔報表的可評分 | `/ 85 可評分` | `/ 100 可評分` |
| 最便宜 Top 10 | 空的 | 有內容 |

「資料來源」那份清單是**由實際命中的 provenance 反推**的，
所以 FinMind 出現在上面就是它真的被用到的證據，不是設定檔的宣告。

### 五、失敗時怎麼看

執行**不會**因為 token 有問題而失敗，這是刻意的——但也代表要主動檢查：

- **名稱拼錯**：報表仍寫「未設定 FINMIND_TOKEN 環境變數」
- **token 無效或過期**：報表的資料缺口會出現 FinMind 回傳的錯誤訊息
- **超出速率限制**：免費方案有每小時請求上限。一次冷啟動約 300 次請求
  （50 檔 × 6 個資料集 + 1），已設 0.6 秒間隔，約 3 分鐘跑完；
  同一小時內重複執行才有機會撞到上限。HTTP 快取為 12 小時，
  當天再跑多半直接命中快取，不會重打。

### 六、token 不會改變來源優先序

FinMind 只**補官方沒有的欄位**，不覆蓋 MOPS 或證交所的數字（規格第十九節）。
設了 token 之後，營收、淨利、資產、權益這些仍然來自官方彙總報表——
可以在逐檔報表的「資料來源」欄逐項核對。

## 評分模型（100 分）

| 項目 | 分數 | 主要指標 |
|---|---:|---|
| Management 管理能力 | 20 | 股本稀釋、ROE 穩定度、盈餘再投資報酬、業外佔比 |
| Moat 經濟護城河 | 25 | 毛利率水準與波動度、營益率韌性、研發費用率、營收規模 |
| ROE 與資本效率 | 15 | 5 年平均 ROE、最新 ROE、ROE 趨勢、權益乘數 |
| 獲利穩定性 | 15 | EPS/營收 CAGR、虧損年數、營益率趨勢 |
| 財務安全 | 10 | 負債比、D/E、流動比、負債／FCF |
| 自由現金流 | 5 | FCF Margin、FCF／淨利、盈再率 |
| Margin of Safety | 10 | 安全邊際（至少 2 種估值法交叉驗證）|

全部門檻寫在 `config/scoring.yaml`，程式碼不寫死任何數字。
報表會列出每個指標的**實際值、命中的門檻帶、得分與資料來源**。

### 三個分數分開看（規格第十一節：好公司 ≠ 好價格）

除了 Buffett Score 總分，每家公司另外輸出
**Business Quality**（企業品質）、**Financial Safety**（財務安全）、
**Valuation**（估值）三個 0–100 子分數，用來分辨
「好公司買太貴」與「便宜但體質差」這兩種完全不同的情況。

### 關於安全邊際的權重

使用者規格第三節寫 Margin of Safety 為 `0~25 分`，第九節的 100 分表寫 `10` 分。
本系統**採第九節**（明確加總為 100 的模型）為預設。

若你偏好第三節的 25 分，改 `config/scoring.yaml` 的 `weights.margin_of_safety` 即可，
系統會自動把總分換算回 100 分制。估值本身不會因權重較低而被淡化——
安全邊際分級（🟢 非常便宜 ～ 🔴 高估）與四種估值法的明細一律完整呈現。

### 估值什麼時候會拒絕出數

估值寧可標示「資料不足」，也不要發布一個看起來很有信心的內在價值。
三道閘門，全部寫在 `config/scoring.yaml` 的 `margin_of_safety.valuation` 下：

| 閘門 | 設定 | 拒絕的理由 |
| --- | --- | --- |
| 可用方法不足 | `min_methods_required: 2` | 單一方法算出的價格不算「交叉驗證過」 |
| 正常化前提不成立 | `normalization_guard` | 取平均是為了抹平**循環**；結構性衰退不是循環，平均值代表的是公司已經失去的獲利能力 |
| 各方法分歧過大 | `dispersion_reject: 0.60` | 兩種方法差逾 1.6 倍，中位數落在兩者之間，沒有任何一種方法支持它 |
| 股數與財報不同基準 | `share_count_tolerance: 0.05` | 股數以「權益 ÷ 每股淨值」交叉驗算；對不上時每股價值會等比例失真 |

> 股數由**三條互相獨立的路徑**決定，取彼此印證的那一組：
> 股本 ÷ 面額、母公司權益（或權益總計）÷ 每股參考淨值、淨利 ÷ EPS。
> 只要兩條相符就採用它們，落單的那條被否決；全部互不相符才回缺料。
>
> 這是實測逼出來的設計。原本預設「股本 ÷ 10」說了算，結果全市場約 2,250 家
> 裡有 298 家對不上——比率高到不可能是面額異常。1103 嘉泥的三個數字是
> 股本 832,874,600、母公司權益 701,385,039、權益總計 704,559,430：
> 兩條權益路徑只差 0.45%，落單的是股本那一條（特別股、庫藏股，或面額不是 10 元）。
> 每次執行的警告會列出各基準的檔數分佈。

被拒絕的安全邊際**不計 0 分，而是退出分母**（可評分滿分由 100 降為 90），
理由與離散度照常顯示在報表上——拒絕計分不等於藏起來。

> 這些閘門都是實際踩到坑之後才加的。可寧衛（8422）EPS 五年 CAGR −41%，
> 5 年平均把它估到 133 元、+81% 安全邊際、「最便宜」榜首；
> 長華電材（8070）殖利率法 49.1 元對上 DCF 368.1 元，中位數 208.6 元、
> +76% 安全邊際、滿分 10/10，而它隱含的自由現金流殖利率是 59%。

### 跨指標調整

有些判斷看的是多個指標的**組合**，單一門檻帶表達不了。目前有一項：

**高 ROE 但高負債**（規格第四、七節：「不能直接給高分」）——
ROE 60% 在任何門檻帶裡都會拿滿分，即使它完全來自 4 倍槓桿。
因此觸發時 ROE 項目的得分上限會壓到可評分滿分的 50%，
並把扣分金額與理由完整寫進報表。此外 BUY 判斷設有財務安全下限，
避免財務結構脆弱的公司靠高總分被判為加碼。

## 絕不編造數字

這是整個系統的設計核心，不是宣示而是結構：

**1. 每個數值都帶出處。** `DataPoint` 封裝 值＋來源＋財報期別＋資料日期，
或是一個「為什麼拿不到」的理由。

**2. 缺料會傳播，不會變成 0。** 所有衍生計算走 `safe_div` / `safe_mean` / `cagr`
等函式，任一輸入缺失，結果就是缺失。除以 0、負股東權益、由虧轉盈的 CAGR
一律回傳「資料不足」而非一個看似合理的數字。

**3. 缺料不計入評分分母。** 資料不全的公司顯示「72 / 85 可評分」而不是「72 / 100」，
後者會讓「查不到資料」看起來像「表現很差」。覆蓋率低於門檻的公司**不進入排行榜**。

**4. 過期資料不當最新用。** 成分股名單全部來源失敗時直接中止分析並回傳非零碼，
不會沿用舊名單產生一份看起來很新的 Dashboard。人工名單超過 45 天即拒用。

**5. 「未檢查」不等於「安全」。** 紅旗報告把資料不足的項目放在 `unchecked`，
報表明白標示，避免一份乾淨的報告被誤讀為已全面確認。

**6. 累計數與單季數分清楚。** 台灣財報以累計數揭露（Q2 是上半年累計）。
系統從資料本身偵測格式並換算，且**拒絕**把只有三季的資料彙總成全年。

## 無法自動偵測的兩項紅旗

規格第十六節列了 16 種警訊，14 種可由財報客觀判定，系統全部實作。
另外兩種——**公司治理重大問題**與**競爭對手市占率快速增加**——
需要重大訊息、法說會與產業市占資料，財報數字裡沒有這些資訊。

硬用財報去近似它們，只會產生看起來很客觀、實際上沒有根據的判斷。
因此系統預設把這兩項標示為「未檢查」，並提供
`data/manual/governance.yaml` 讓你手動登錄——有登錄才觸發。

同理，Moat 的品牌、客戶黏著度、網路效應等面向，量化代理指標只能近似。
`config/overrides.yaml` 可覆寫 Management 與 Moat 的任一子項，
但**必須填寫理由與檢視日期**（缺任一項會被拒絕並報錯），
報表會標示「人工調整」、原始計算值與你的理由；超過一年未更新會標示「覆寫已過期」。

## 疑難排解

| 症狀 | 處理 |
|---|---|
| `無法取得成分股名單，已中止分析` | 這是預期行為，不是 bug。先手動觸發 `probe-sources.yml` 看端點實際回什麼；臨時解法是在 `data/manual/constituents.yaml` 填入最新名單與 `as_of` 日期 |
| 成分股權重合計只有約 95% | 正常。權重是佔基金淨值比例，其餘為現金與期貨部位 |
| 大量指標顯示「資料不足」 | 多半是沒設 `FINMIND_TOKEN`；`make verify` 會列出各來源狀態 |
| 某些財報欄位對不上 | 來源 API 調整了科目命名。`make verify` 會列出**實際回傳**的所有科目名稱，據以修正 `sources/finmind.py` 的對應表 |
| 分數與預期不符 | 逐檔報表列出每個指標的實際值、命中門檻與資料來源，可直接追到是哪一項造成差異 |
