# 00929 Buffett Investment Monitor

針對 **00929 復華台灣科技優息 ETF** 全部成分股的巴菲特式 3M 選股
（Management / Moat / Margin of Safety）與財報即時追蹤系統。

每次執行會：抓取最新成分股名單 → 逐檔載入財報 → 計算指標 → 交叉驗證估值 →
偵測紅旗 → 產生 100 分 Buffett Score → 與上次結果比對 → 輸出 Dashboard 與報表。

## 資料來源（規格第十九節：官方優先）

| 用途 | 來源 | 說明 |
|---|---|---|
| 成分股名單 | 證交所 ETF 申購買回清單（PCF）→ 復華官網 → 人工名單 | 依序嘗試，**全部失敗即中止** |
| 最新一期財報 | 證交所／櫃買中心 OpenAPI | 官方權威值，免金鑰 |
| 5–10 年歷史 | FinMind v4 | 需免費 token |
| 股價、本益比、殖利率 | 證交所 `BWIBBU_ALL`、`STOCK_DAY_ALL` | 官方每日 |

**為什麼需要 FinMind**：實測確認證交所 OpenAPI 的每個端點都**只回傳最新一期**，
不接受日期參數。而 EPS/營收 CAGR、5 與 10 年平均 ROE、毛利率趨勢、
歷史本益比分位都需要多年序列，因此歷史由 FinMind 回補。

免費 token 於 <https://finmindtrade.com> 註冊取得，設為環境變數 `FINMIND_TOKEN`。
**未設定不會中斷執行**，但所有需要歷史的指標會標示「資料不足」，
而不是用單期資料假裝成多年平均。

> 00929 追蹤的是「特選臺灣**上市上櫃**科技優息指數」，成分股含上櫃公司，
> 所以同時接了櫃買中心的端點。

## 評分模型（100 分）

| 項目 | 分數 | 主要指標 |
|---|---:|---|
| Management 管理能力 | 20 | 股本稀釋、ROE 穩定度、盈餘再投資報酬、業外佔比 |
| Moat 經濟護城河 | 25 | 毛利率水準與波動度、營益率韌性、研發費用率、營收規模 |
| ROE 與資本效率 | 15 | 5 年平均 ROE、最新 ROE、ROE 趨勢、權益乘數 |
| 獲利穩定性 | 15 | EPS/營收 CAGR、虧損年數、營益率趨勢 |
| 財務安全 | 10 | 負債比、D/E、流動比、負債／FCF |
| 自由現金流 | 5 | FCF Margin、FCF／淨利、盈再率 |
| Margin of Safety | 10 | 安全邊際（至少 2 種估值法交叉驗證）|

全部門檻寫在 `config/scoring.yaml`，程式碼不寫死任何數字。
報表會列出每個指標的**實際值、命中的門檻帶、得分與資料來源**。

### 三個分數分開看（規格第十一節：好公司 ≠ 好價格）

除了 Buffett Score 總分，每家公司另外輸出
**Business Quality**（企業品質）、**Financial Safety**（財務安全）、
**Valuation**（估值）三個 0–100 子分數，用來分辨
「好公司買太貴」與「便宜但體質差」這兩種完全不同的情況。

### 關於安全邊際的權重

使用者規格第三節寫 Margin of Safety 為 `0~25 分`，第九節的 100 分表寫 `10` 分。
本系統**採第九節**（明確加總為 100 的模型）為預設。

若你偏好第三節的 25 分，改 `config/scoring.yaml` 的 `weights.margin_of_safety` 即可，
系統會自動把總分換算回 100 分制。估值本身不會因權重較低而被淡化——
安全邊際分級（🟢 非常便宜 ～ 🔴 高估）與四種估值法的明細一律完整呈現。

### 跨指標調整

有些判斷看的是多個指標的**組合**，單一門檻帶表達不了。目前有一項：

**高 ROE 但高負債**（規格第四、七節：「不能直接給高分」）——
ROE 60% 在任何門檻帶裡都會拿滿分，即使它完全來自 4 倍槓桿。
因此觸發時 ROE 項目的得分上限會壓到可評分滿分的 50%，
並把扣分金額與理由完整寫進報表。此外 BUY 判斷設有財務安全下限，
避免財務結構脆弱的公司靠高總分被判為加碼。

## 絕不編造數字

這是整個系統的設計核心，不是宣示而是結構：

**1. 每個數值都帶出處。** `DataPoint` 封裝 值＋來源＋財報期別＋資料日期，
或是一個「為什麼拿不到」的理由。

**2. 缺料會傳播，不會變成 0。** 所有衍生計算走 `safe_div` / `safe_mean` / `cagr`
等函式，任一輸入缺失，結果就是缺失。除以 0、負股東權益、由虧轉盈的 CAGR
一律回傳「資料不足」而非一個看似合理的數字。

**3. 缺料不計入評分分母。** 資料不全的公司顯示「72 / 85 可評分」而不是「72 / 100」，
後者會讓「查不到資料」看起來像「表現很差」。覆蓋率低於門檻的公司**不進入排行榜**。

**4. 過期資料不當最新用。** 成分股名單全部來源失敗時直接中止分析並回傳非零碼，
不會沿用舊名單產生一份看起來很新的 Dashboard。人工名單超過 45 天即拒用。

**5. 「未檢查」不等於「安全」。** 紅旗報告把資料不足的項目放在 `unchecked`，
報表明白標示，避免一份乾淨的報告被誤讀為已全面確認。

**6. 累計數與單季數分清楚。** 台灣財報以累計數揭露（Q2 是上半年累計）。
系統從資料本身偵測格式並換算，且**拒絕**把只有三季的資料彙總成全年。

## 無法自動偵測的兩項紅旗

規格第十六節列了 16 種警訊，14 種可由財報客觀判定，系統全部實作。
另外兩種——**公司治理重大問題**與**競爭對手市占率快速增加**——
需要重大訊息、法說會與產業市占資料，財報數字裡沒有這些資訊。

硬用財報去近似它們，只會產生看起來很客觀、實際上沒有根據的判斷。
因此系統預設把這兩項標示為「未檢查」，並提供
`data/manual/governance.yaml` 讓你手動登錄——有登錄才觸發。

同理，Moat 的品牌、客戶黏著度、網路效應等面向，量化代理指標只能近似。
`config/overrides.yaml` 可覆寫 Management 與 Moat 的任一子項，
但**必須填寫理由與檢視日期**（缺任一項會被拒絕並報錯），
報表會標示「人工調整」、原始計算值與你的理由；超過一年未更新會標示「覆寫已過期」。

`.github/workflows/daily-update.yml` 於台灣時間週一至週五 18:30 執行：
驗證設定 → 跑測試 → 更新分析 → 把 `data/snapshots`、`docs`、`reports` commit 回 repo。
當日的評分變化與紅旗會寫進 commit 訊息，所以 `git log` 本身就是變化歷史。

需在 repo 設定 `FINMIND_TOKEN` secret（未設定仍會執行，但長期指標標示資料不足）。

## 疑難排解

| 症狀 | 處理 |
|---|---|
| `無法取得成分股名單，已中止分析` | 這是預期行為，不是 bug。檢查網路，或在 `data/manual/constituents.yaml` 填入最新名單與 `as_of` 日期 |
| 大量指標顯示「資料不足」 | 多半是沒設 `FINMIND_TOKEN`；`make verify` 會列出各來源狀態 |
| 某些財報欄位對不上 | 來源 API 調整了科目命名。`make verify` 會列出**實際回傳**的所有科目名稱，據以修正 `sources/finmind.py` 的對應表 |
| 分數與預期不符 | 逐檔報表列出每個指標的實際值、命中門檻與資料來源，可直接追到是哪一項造成差異 |
